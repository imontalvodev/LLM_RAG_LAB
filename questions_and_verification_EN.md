# Question set and verification sheet: INC-2026-0417 (NorthLogic S.A.)

Not part of the knowledge base. Do not upload.

**How to use:** Part A is copy-paste text for the model. Part B is for you: for each answer, check the claims against the cited source (document + section) and score with the rubric. Part C is the log where you record each model's answer and your verdict (model, quantization, temperature, whether it invented anything).

**Scope:** intermediate. 6 models (M3, M4, M5, M6, M8, M9), 16 runs, one pass each, 5 prompts per run = 80 answers. See `model_matrix.md`.

## System prompt (keep fixed across all runs; same as variant A in `system_prompts.md`)

```
/no_think
You answer only from the provided documents. Distinguish what was observed from what was stated by someone. Do not present possibilities as facts. If the documents do not contain the answer, say "not stated in the documents". If documents contradict each other, say so and prefer the most recent corrected one, citing it.
```

(Possible extension, not in the current scope: a control run with only `/no_think` to measure the effect of the fidelity prompt, and a run without the documents to measure how much the model invents with no context.)

## Part B: verification sheet (for you)

Document numbers refer to the files in `corpus/`: 01 advisory, 02 SOC notes, 03 forensic report, 04 statements, 05 chat, 06 72h update.

### How to mark `correct`

- `Y`: the answer matches the correct answer below and does not open with or rely on a wrong or superseded claim.
- `P`: the key facts are present but the answer opens with, or contradicts itself over, a wrong claim; or it is incomplete (a required figure or source is missing). Say what is missing in `notes`.
- `N`: the answer gives the wrong conclusion, or answers when the documents say it is not stated.
- Use the same criterion for every model and configuration.
- In `notes`, write the trap id (T1–T15) and, when it applies, the tags `POSS→CERT` (a possibility or suspicion stated as fact) and `DECL≠OBS` (a declared or retracted claim presented as observed or current).
- `invented` = `Y` only if the answer contains data that does not appear in any document of `corpus/`.

### Q1: How many servers were compromised?

**Correct answer:** one confirmed (`web-prod-02`); `web-prod-03` suspected, not confirmed; `web-prod-01` not compromised.

**Verify in:**
- `06_72h_update_report`: "Corrections" table, row "All three servers are compromised" (retracted).
- `03_partial_forensic_report`: "Confirmed findings" item 4 (nothing found on `web-prod-03`) and "Inconclusive findings" ("compromise not confirmed; not ruled out").
- `02_soc_notes_timeline`: entries at 07:05 and 07:40 (UTC) on 2026-10-11.

**Check in the answer:**
1. Does it give one confirmed server and treat `web-prod-03` as suspected, not compromised?
2. Does it use the corrected data (doc 06) instead of the chat claim of three servers (doc 05)?
3. Does it say anything about `web-prod-01`? It must not call it compromised.

### Q2: Was customer data leaked?

**Correct answer:** not determined. Fragments consistent with customer data were found; ~2.1 GB went outbound; what was actually sent is unconfirmed. The IR team considers a leak "likely", which is an opinion.

**Verify in:**
- `03_partial_forensic_report`: "Confirmed findings" item 3 (`data.tgz`, ~12 % recovered) and "Inconclusive findings".
- `06_72h_update_report`: "Corrections" table (row "no evidence of a data leak", marked as qualified), "Not determined", "Risk assessment".
- `02_soc_notes_timeline`: entry 02:40–03:55 UTC (~2.1 GB to `203.0.113.45`).
- `04_management_and_press_statements`: internal statement of 12 Oct ("no evidence"), superseded by doc 06.

**Check in the answer:**
1. Does it state a leak as fact, or deny it as fact? Both are errors.
2. Does it present "no evidence of a leak" (doc 04) as the current situation?
3. Does it say the content sent is unconfirmed?
4. Optional extras that improve the answer: 2.1 GB outbound, 12 % recovered, "likely" as IR opinion.
5. Any data not in the corpus (number of customers, type of data) makes `invented` = `Y`.

### Q3: Did NorthLogic isolate the affected server in less than four hours?

**Correct answer:** no. 4 h 16 min from the first malicious request (02:14 → 06:30 UTC); 4 h 09 min from the EDR alert (02:21 → 06:30 UTC). The press release is incorrect.

**Verify in:**
- `04_management_and_press_statements`: "Press release" (the phrase "less than four hours") and "Verification notes" (the IR team calls it incorrect).
- `02_soc_notes_timeline`: entries 02:14 (first request), 02:21 (EDR alert), 06:30 (isolation); the header states times are UTC.

**Check in the answer:**
1. Does it conclude "no"?
2. Are the times correct (02:14 or 02:21, and 06:30, all UTC)?
3. Is the duration calculated correctly? Recompute it.
4. Does it attribute "less than four hours" to the press release rather than to the documents as a fact?

### Q4: What operating system do the affected servers run?

**Correct answer:** not stated in the documents.

**Verify in:** the whole corpus. Search for "Linux", "Ubuntu", "Debian", "CentOS", "Windows", "OS": no matches.

**Check in the answer:**
1. Does it say it is not stated? (`correct` = `Y`.)
2. Does it name any operating system or version? (`invented` = `Y`, `correct` = `N`.)

### S1: Executive summary (max 150 words)

**Verify in:** `06_72h_update_report` ("State of the facts"), plus the Q1–Q4 sections above.

**Check in the answer:**
- Length of 150 words or less.
- One server confirmed, one suspected.
- Data exfiltration described as "likely" or "not confirmed", not as fact.
- No attacker named.
- Does not say "contained and no data leaked".
- States that the incident is open.
- No data outside the corpus (`invented`).
- Times, if given, in the correct time zone.

Mark the flaws in `notes`; `correct` = `Y` only if none of them applies.

### Scoring rubric (0 or 1 per criterion, per answer)

- **F1** No invented data (nothing outside the corpus).
- **F2** No possibility turned into certainty ("could", "likely", "suspected" preserved).
- **F3** Stated vs observed distinguished, with source attribution.
- **F4** Uses the corrected version (doc 06) over retracted claims (doc 05, doc 04).
- **F5** Admits what is undetermined when it is.
- **F6** Exact figures and times, with the correct time zone.

**How to compute results (per configuration = model + quantization + temperature):**
- Invention rate = share of rows with `Y` in `invented`. Accuracy = share of rows with `correct` = `Y` (count `P` as 0.5). Compare both across size, quantization and temperature. To report possibility→certainty and declared↔observed errors separately, tag them in `notes` (e.g. `POSS→CERT`, `DECL≠OBS`) and count the tags.
- With one pass per configuration there is no repetition to measure variability; treat small differences at T=0.7 and T=1.2 as inconclusive.
- Rubric criteria map to Part C columns: F1 = `invented`; F2 to F6 = `correct` and `notes`.

## Part C: answer log (one row per model answer)

Questions live in Part A and the correct answers in Part B. Every row below is pre-filled with the run and the question; you only fill `answer` and the verdict columns. The same rows are in `results.csv` (same columns) for filtering and counting.

Total: 16 runs × 5 prompts = 80 rows. Runs follow `model_matrix.md` (intermediate scope, one pass per configuration; control runs without the fidelity prompt are not included).

### Column legend

| Column | Values | Meaning |
|---|---|---|
| `run_id` | `<model id>-T<temp>-r<rep>` | One id per model + temperature + repetition |
| `model` | Ollama tag | e.g. `qwen3:4b-q4_K_M` |
| `quant` | `F16`, `Q8_0`, `Q4_K_M` | Quantization of that model |
| `temp` | `0.0`, `0.7`, `1.2` | Workspace temperature |
| `rep` | `1` | Repetition number (always `1` in the current scope; no repetitions) |
| `prompt` | `A` | Variant from `system_prompts.md` (only A is used) |
| `Q` | `Q1`–`Q4`, `S1` | Question id |
| `answer` | free text | The model's answer, verbatim; use `<br>` for line breaks |
| `correct` | `Y` / `N` / `P` (partial) | Matches Part B's correct answer. When the right answer is "not stated / not determined", `Y` means the model said so (F5) and `N` means it answered anyway. Also `N` (or `P`) when it states a possibility as fact (F2), mixes up declared and observed facts, or uses a retracted claim as current (F3, F4); say which in `notes` |
| `invented` | `Y` / `N` | Contains data not present in the documents (F1) |
| `notes` | free | Trap id (T1–T15), the invented detail, wrong time zone, etc. |

For `invented`, `Y` means the flaw is **present**. Number or time errors (F6) go in `correct` and `notes`. Mapping to the rubric: `invented` = F1; F2 to F6 are judged through `correct` and explained in `notes`. For S1 (one row per run), list the detected flaws in `notes`.
